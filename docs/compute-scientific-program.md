# Two tracks, one controlled scientific narrative

This phase implements the **presentation and evidence boundaries**, not new benchmark results or the later Intelligence Efficiency Frontier explorer. No GPU runs were performed and no literature result was relabelled as the author's work.

## Public contract

- Inference objective: make identical cognition cheaper. Hold checkpoint, prompt/template, candidates, token budget, verifier, quality rule, seed policy and workload constant within a runtime comparison. Precision-changing methods require a separate quality-constrained experiment.
- Post-training objective: improve verified final-answer accuracy across actual inference GPU-cost budgets. Base → SFT → correctness RLVR/GRPO → efficiency-aware RLVR is an evaluation ladder; the last checkpoint is a planned extension, not an implemented achievement.
- Composition design: Base/Static, Base/Optimized, Post-trained/Static, Post-trained/Optimized. “Optimized” denotes execution; it must not silently switch the model or train a new efficiency-aware checkpoint.
- Every operational scene is labelled **illustrative**. The evidence glossary separately defines implemented, profiled, measured, planned and illustrative. An implementation link is not a measurement.
- The earlier +27%, +31% and +46% figures are withheld from the public lab. Baseline, split, sample size, exact metric, confidence interval, compute matching and evaluator independence are not supplied. They are not homepage proof, conclusion proof, or result points.

## Measurement rules for the next phase

1. Count one selected final answer per task. It must be valid and externally correct, not merely passed by the search verifier. Record invalid outputs, rejected candidates, timeouts, retries and false positives.
2. Primary proposed cost boundary is allocated GPU-seconds summed across devices and the complete run. Record generator/draft, verifier/selection, retries and failed work. Declare warm-up, idle allocation and shared-batch attribution; do not double-count overlapping requests. Active device time and wall time are separate diagnostics.
3. GPU-seconds per valid correct answer is total declared GPU cost divided by the number of externally correct final answers. Zero correct answers produces undefined/NA (or explicitly infinite cost), not a smoothed good-looking value.
4. Freeze a p95 end-to-end latency limit and correctness non-inferiority margin before comparing runtimes. Retain timeout/failure accounting.
5. Distinguish development, model-selection validation and locked confirmatory holdout. Never tune a checkpoint, verifier, budget or narrative using the final holdout. Record contamination checks and holdout access.
6. Audit negative flips (old-correct → new-wrong) alongside positive flips. Replicate with a frozen protocol. Add task-paired uncertainty and appropriate seed clustering; preserve the raw contingency counts.
7. TTC-AUC is a **proposed study metric**, not an assumed universal convention. Freeze linear/log actual-cost axis, common measured range, interpolation, normalization and uncertainty procedure. Nominal 1×/2×/4×/8× candidate or token caps are not actual GPU costs. A possible normalized trapezoidal integration over measured cost points must not be replaced by equal weights on nominal budget rungs. Do not extrapolate unmeasured endpoints or silently impose a monotonic envelope.
8. Build an empirical Pareto frontier only from comparable conditions passing the quality/latency gates. For the requested axes, a point dominates another only when accuracy is no lower and GPU-seconds per correct final answer is no higher, with at least one strict improvement. Show uncertainty and acknowledge crossing/non-dominated curves.

## Presentation behavior

`compute-study.tsx` delegates to a linked, explicitly synthetic results laboratory. The original architecture and microscope remain the first two acts. The third act has three views per project, all generated by `app/compute/lab-simulation.ts`, not by altered literature scores. See [the laboratory design and model](results-laboratory.md).

Inference links a four-condition Pareto diagram, a prefill/decode work decomposition, and a queue-inclusive latency trace. Post-training links a paired 96-task capability map, four policy curves at four thought allowances, and a weighted gain/loss flow audit. Nominal allowances and actual simulated cost coordinates are different quantities.

Every figure visibly says synthetic/illustrative. A selected run has a native evidence dialog and downloadable per-task JSON. No real checkpoint, hardware, runtime, verifier, confidence interval, or raw benchmark artifact is invented. The scientific contract stays available beneath the figure, not in place of the figure. The real Qwen3-4B measurement program is still pending.

## Primary-source reference shortlist

Two user-requested Luna xhigh agents independently researched references and audited metric/evidence semantics. The main implementation also checked the primary repositories below. These are **methodology references, not project evidence**:

| Reference | Useful starting point | Boundary |
|---|---|---|
| [Open-R1](https://github.com/huggingface/open-r1) | SFT and GRPO scripts, recipes, reward/evaluation plumbing | Pin revisions and adapt hardware; its demonstrations do not supply this portfolio's GPU-cost measurements. |
| [s1](https://github.com/simplescaling/s1) | Released model/data, training/evaluation scripts, explicit budget forcing | Token limits, EOS suppression and continuation instructions are controls, not measured GPU-seconds. |
| [Search and Learn](https://github.com/huggingface/search-and-learn) | YAML run recipes for Best-of-N, beam search and diverse verifier tree search | Preserve selection/verifier cost and distinguish candidate-bank diagnostics from final-answer accuracy. |
| [LACONIC](https://github.com/Debugger001/LACONIC-LLM) | Length-aware RL with task reward and an adaptive excess-length penalty | A candidate reference for the planned efficiency-aware extension; shorter outputs are not proof of this project's runtime savings. |

No model training or GPU evaluation was performed. Additional primary references are the [MiMo technical report](https://arxiv.org/html/2505.07608v2) and [SGLang v0.4 serving report](https://www.lmsys.org/blog/2024-12-04-sglang-v0-4/). Their mechanisms inform the research notes, not the synthetic simulator's output values. An independently retokenized, pinned six-run s1 reference fixture is retained in `app/compute/s1-reference.json`; `scripts/reproduce-s1-reference.py` documents reproduction from released samples and tokenizer files without loading model weights. This research fixture is not imported into the public synthetic lab.

# Visual consequence playbook

## October 23: preserve time, identity and qualification

- **A hold is presentation time, not extra work.** Map one presentation cursor to an immutable event trace. Export both coordinates. A longer explanatory pause must not increase service latency or GPU cost.
- **Make the constrained object visible.** A one-page shortfall should originate at the missing page, not at an arbitrary card icon. Label fixed placement assumptions so the viewer does not have to guess why another replica cannot be used.
- **Follow dependencies, not independent correctness badges.** A rejected speculative token invalidates the draft suffix. Draw later ordinary target tokens sequentially; do not imply that downstream proposals passed a separate check.
- **Close one cohort before introducing another.** Preserve actual token/request identities in the ending. If a new example is needed to teach latency targets, name the population and observation window at the transition.
- **Change the gate without rewriting the trace.** Threshold controls can expose why a request qualifies, while token times, validation and cancellations stay fixed. Invalid answers must not become valid because a latency target is loosened.
- **Qualification is an intersection.** Show completion, TTFT, stream gap and validity separately before composing them. Keep the offered cohort and time window explicit; completion rate is not qualified-delivery rate.
- **Check the real visible surface.** Mounted hidden panels can pass DOM queries while screenshots show an unrelated page. Assert visibility, then inspect moving and settled states. Resize the viewport after selecting a late chapter to catch navigation that disappears offscreen.
- **Retire unreachable implementations.** Once every state routes to the new scenes, remove the obsolete renderer and inspection state. One director and one active rendering path make later polish safer.

## October 23: admission is not delivery

- Show each limiting resource in its own units. A token-work budget and a KV-page pool can disagree; a single generic capacity meter conceals that decision.
- Distinguish a proposed reservation, an admission snapshot and current ownership. A successful historical decision must not masquerade as live resource usage later in the story.
- Keep deferred work visible. Splitting a request is not deleting its input; completed prefill must also stop displaying deferred work as pending.
- Passing a gate is not the final user outcome. Retain the already-streaming answer so its next-token interruption can expose the consequence of the admitted work.
- Connect the exact retained state to the next mechanism. Two cached prefix pages are a more useful handoff than an unexplained total pool occupancy.
- Scope inspection to a transport revision. A stale pin must not return just because the user revisits the same timestamp.
- Inspect manual seeks as well as autoplay. A chapter paused on the first frame of a reveal can strand its connector at zero length; provide readable moment targets and settled reduced-motion views.

Applied in `serving-admission-checkpoint-20261023.md`. Use these principles for future policy and runtime scenes without copying the admission layout.

## October 13: execution format and device ownership

- Separate what an optimization removes from what it changes. Fusion removes a temporary memory round trip; quantization also changes represented values. They cannot share an unconditional “same output” claim.
- Show intermediate values, not only renamed boxes. A four-value arithmetic example can make the missing write/read leg inspectable without pretending to profile a whole GPU.
- Finish a collective visually. A sum at a central node is only half the all-reduce explanation; show the result returning to both participants.
- Preserve request color through pipeline stages and retain empty slots. A fully illuminated grid hides fill/drain costs and teaches the wrong capacity story.
- Return from a microscope to the original identities. Cancellation must release the cancelled request's pages, not clear the whole pool for visual convenience.
- Make the consequence connector avoid labels and data marks. Check the final rendered path, not merely its endpoint coordinates.
- Size the whole comparison before enlarging individual type. Compact descriptive headings and a bounded stage kept the tested desktop figure readable in one view; mobile uses explicit pan shortcuts instead of shrinking the numbers into illegibility.
- Keep mathematical examples separate from measured performance and from other local fixtures. Export the selected arithmetic/state; never compose unmeasured speedups across independent demonstrations.

Applied in `serving-hardware-checkpoint-20261013.md`. Remaining older overview scenes still need their own directed treatment.

## October 13: less work is not always earlier delivery

- Make reuse and admission separate visible facts. A ready prefix is useful state, not permission to overwrite another request's live pages.
- Keep reused pages in place; display the block-table mapping when new pages are noncontiguous. Ownership and readiness are different dimensions.
- Show both the input work avoided and the waiting it encounters. The consequence is the difference between those effects, not the cache-hit label alone.
- Earn a sensitivity plot with a concrete request first. Preserve the original event trace while a separately labeled probe varies one condition; export both identities.
- Hold the crossover as deliberately as the win. A tie or cold-route advantage teaches when the optimization should not dictate placement.
- End by reclaiming only the completed request's private state. A final answer without visible resource release leaves the serving story unfinished.
- Connect the currently visible bracket, not a hidden earlier diagram's marker, to the consequence. Retain exact units at both ends.
- Reserve card geometry across the whole film and clamp the final display to its exact endpoint. A clock stopping one frame short must not make replay fail.
- Do not let graph dragging steal native touch panning in a narrow diagram. Keep a reachable alternate slider and keyboard path.
- Quiet geometry without making its labels unreadable; account for fixed site controls when checking mobile headings.

## October 9: a saved operation is not automatically saved cost

- Show acceptance as a prefix boundary, not independent green checkmarks. A rejected conditioning token invalidates later proposals even if a later word looks plausible.
- Keep provisional work out of the output ribbon. Move accepted units and the target correction into it only at the commit event, and preserve each unit's origin in later views.
- Expand one operation, then repeat it faster without cycling the headline at every micro-phase. Persistent output and round identity can carry the repetition.
- Transform the completed mechanism into its accounting, not a generic end slide: each round visibly contains committed and discarded positions.
- Count serial target calls, evaluated target positions and additional draft units separately. Fewer calls alone is not a latency or GPU-cost result.
- Put the failing case on the same controls. No acceptance should retain the baseline call count and expose extra work, without a decorative gain connector.
- Put narrow-screen navigation hints before the diagram, where they can be discovered. Load navigation styling with its parent, not a lazy child.

## October 1: camera changes must preserve computation

- Audit visibility against the authored clock, not just the existence of an SVG. A beautiful suffix/attention sequence taught nothing when the view switched away before its animation started.
- Expand the short operation, then carry its exact service cursor, token count and request identity into the next representation. A brief camera handoff can hold the clock; it must not restart the request.
- At early completion, both serial workers have spent equal time **so far**. Only one has finished. Distinguish accumulated work from total work to finish the request; the latter is the correct comparison for the final saving.
- Hold the completed lane against the still-running lane, then let the remaining work visibly accrue before the final percentage appears. Use the actual interval bracket as the result-card connector source.
- Stable stage/card geometry prevents explanatory playback from becoming a moving target. Invisible scenes must be inert and removed from accessibility; reduced motion must not leave a half-faded composition on manual seek.
- A no-match case needs equal lanes, zero saving and no gain connector. Keep the limitation in the visual result, not only in a footnote.

## September 29 finale: units and scope are part of the story

- A composition should show ordered counterfactuals, not add independent speedup percentages. Keep the previous intervention enabled while applying the next; derive each increment from those two actual conditions.
- Scheduling saves waiting; prefix reuse saves input computation; faster execution lowers the remaining per-token cost. Show waiting and work in separate visual columns, with their units, before composing the GPU-cost result.
- A request-level saving is not the cohort's average. Expand to the complete task set before changing the denominator. Include unsuccessful attempts in the total cost, with the same correct-outcome denominator on both sides.
- Preserve the explanation at zero gain. Different documents leave prefix-reuse work unchanged; no decorative gain bracket or connector should appear.
- Connect the contribution bracket to its card, and put the contribution amounts inside the final saved-work segments too. Matching colors alone do not explain the arithmetic.
- Reserve card height across authored beats. Do not recenter the entire explanation whenever a title wraps or an equation becomes longer. Quiet the unchanged metric without removing the surrounding system.
- A finale may use precise comparison geometry instead of duplicating the earlier hardware animation. Its job is to make the accumulated mechanism accounting legible, not add another decorative machine.

## September 29 follow-up: a labeled total is not an explained contribution

- Put the intermediate condition on the plot. A sidebar label cannot explain a jump if the graph still shows only total endpoints. Plot the same conditional counterfactual that supplies the number.
- One reading step, one dimension. Quiet secondary values while explaining cost or accuracy, but preserve their inspectability and never hide a real tradeoff from the data.
- Hold baseline, each intervention, final condition and difference separately. Do not make metric hover advance the narrative.
- Reserve readout geometry before changing copy or numbers. A shifting sidebar can move an entire centered chart even when the SVG coordinates never change.
- A section title names its question, not its selected record. “Input processing cost” is the heading; “Request 7” is context.
- Distinct scopes deserve distinct clocks. A prefill-only comparison ends at prefill completion, not answer completion; a decode-only comparison begins at decode zero. Update geometry, counters and completion language together.
- An opening can introduce the accounting without declaring the result. Follow a named request through the unchanged system before introducing interventions.

## The test

A visitor who ignores the paragraphs should still see what changed, what stayed fixed, and why the change matters. An impressive technical breakdown that does not communicate usefulness is unfinished.

### September 27: connect a claim to its origin

- A matched color is helpful but insufficient. The result needs a traceable origin: an interval bracket, a population increment, or an event-derived completion endpoint. Connect that origin to the corresponding baseline, optimized, or Δ value during its authored hold.
- Grouped marks require exact partial accounting. Five requests per mark means a sixth request fills one fifth of the next mark; the increment bracket must start after the shared portion, not at the beginning of its row.
- A comparison can change meaning at completion. Before both queues clear, the difference is completed requests at a clock time. Afterwards, it is the interval between clearance events. Update the diagram, unit and result together.
- Connectors are annotations, not controls. Keep them pointer-transparent; remove cross-panel routing in a stacked layout and retain matching local anchors. Do not draw a gain connector for a zero-increment capacity frame.
- Put the cause next to the gain. Execution-rate sensitivity, prefix reuse and scheduling are different interventions. Do not let a common purple result card erase that distinction.
- Type checks and deterministic model tests cannot accept delegated visual direction. Watch the result as a visitor; a correct static architecture diagram may still fail the intended experience.

The narrative links three scales:

1. **Mechanism:** the exact state, operation or equation that changes.
2. **Consequence:** the local difference, visible in the same coordinates.
3. **Practical value:** what this lets a request, worker, agent or user do next.

The audience should discover the conclusion through the image, not decode our implementation notes. Preserve technical substance while reducing presentation clutter.

## What the reviews established

- The rich memory, compute and token SVGs work. Do not replace them with anonymous boxes or bars when simplifying the screen.
- A worker visibly becoming free is stronger than a generic speedup headline. Carry that released state into its next useful action.
- Make the difference the focal object: bracket it, thicken it, connect it to the consequence. A subtle thin line is insufficient for the pivotal moment.
- A restrained warm-red emphasis can identify the reference's extra work. No siren/strobe, no implication of model failure, no full-page flashing.
- A contract-response text box does not, by itself, demonstrate practical value. Show a request being admitted, completed, recovered or served sooner.
- More completed requests in a fixed interval is not more simultaneous workers. Keep worker count, outstanding demand and completion count distinct.
- An unexplained p95 curve is not a learning experience. Earn that curve by showing waiting and completion first, or put it in inspection.
- A cumulative cost chart needs a visible interpretation. Attach the saved-work region to the resource or capability it makes available.
- The prefix mechanism is visually strong, but its benefit must be legible. Bring avoided work and the next request's shorter input phase into the foreground.
- A fixed sidebar filled with prose uses valuable mechanism space without improving comprehension. Replace it with a visual consequence or remove it.
- Repeated titles, legends, slogans, default inspector text and narrative captions compete. Keep one main sentence, direct labels and an earned result.
- Important numbers need scale and nearby units. Supporting assumptions need smaller type and disclosure, not equal-size boxes.
- Do not enlarge all text inside unchanged containers. Rebalance the entire perimeter: diagram, direct annotations, available space and reading order.

## Screen composition

- Start with approximately 60–70% mechanism and 30–40% consequence when both need to be visible. These are starting proportions, not fixed laws.
- Use a callout as an annotation connected to the exact interval, curve segment or state. A detached large statistic is not enough.
- A brief focus pull may soften nonessential context locally. Do not blur the entire page, conceal controls, trap focus or obscure evidence status.
- Keep surrounding architecture visible but quieter. Spotlighting is not deletion.
- Put assumptions, raw records and detailed mathematics behind explicit controls. Do not hide the illustrative status or change units to make a result look stronger.
- Show scientific boundaries once clearly, then make their consequences visible. Avoid repeatedly narrating internal accounting vocabulary.

## Playback direction

Establish → act → expose the difference → hold long enough to register → carry the changed state forward.

The reveal must have a reason and a stable identity. A request does not disappear when a chart appears; its service interval or outcome carries into the next scale. Use one reversible clock for mechanism activity, counters, deltas and phase transitions. Seeking must reconstruct a coherent state, not leave old DOM state paired with a new timestamp. Test external pause and pinned inspection, not only the local slider.

No mandatory watch time. Every moment is directly selectable. Reduced motion opens a meaningful settled state, while manual inspection remains available. Avoid independent decorative loops, repeated full-screen fades and animations that imply unmeasured telemetry.

Test what the browser actually does when it brings a control into view. A transition wrapper with `overflow: hidden` can become a silently displaced scroll container; use non-scrolling clipping when that is the intent. Validate computed typography too: an unresolved custom-property font shorthand can make a major payoff inherit body-sized text. Test a zero-delta early frame as well as the dramatic endpoint; the caption must not claim a lead before one exists.

## Numerical discipline

Examples such as “42 versus 32” communicate a desired comparison, not supplied benchmark measurements. Calculate every displayed count from declared assumptions. Preserve the distinction between service time, queued response time, summed busy GPU-seconds, allocated GPU billing, worker count and requests completed. Simulated values remain illustrative.

A burst of 1,000 simultaneous requests can queue behind two workers; it is not 1,000 parallel executions. Cache outcomes held fixed for a service sensitivity replay do not establish cache readiness under new arrivals. Explain that boundary in inspection. Do not infer real serving capacity, kernel attribution or quality improvements from schematic geometry.

## Scale without changing the claim

The September 24 execution pass adds three useful decisions for later components:

- **Carry an identity through the zoom.** Q7's worker release becomes Q8's earlier start, then a twelve-request waterfall. Camera range and playback speed can change; start/finish events cannot. A descending row denotes request order, never an additional worker.
- **Name the denominator visually.** A fixed GPU-work allowance gets two equal budget rules and a population difference. An elapsed-time comparison gets a common clock, workers and completion steps. Do not use the same large-number panel for both without exposing that distinction.
- **Reveal the counterexample at the endpoint.** Once both queues finish, the completion lead is zero. The result changes to earlier clearance, not a misleading permanent throughput count. This is an earned conclusion, not an inconvenient state to hide.
- **Variation belongs in inputs.** A varied workload chooses prompt/output lengths reproducibly, then runs the same scheduler. Never add irregularity to the line to imitate real telemetry. A large event count can legitimately look smooth when zoomed out.
- **Keep inspection subordinate but exact.** A chosen request freezes the film; the exported record captures the same clock, task order and budget. Endpoint access must be exact, including slider quantization. Native sliders with floating maxima can otherwise strand the last request.
- **A transition must not move the controls.** Reserve the contextual-control row. Outgoing scenes are inert and positioned out of layout so an expanded hidden inspector cannot keep later scenes artificially tall. Narrow screens prioritize a readable figure and a stacked consequence over tiny whole-system type.
- **Use one stronger result, not more text.** A localized violet increment and its fixed allowance teach more than a slogan plus five explanatory sentences. Hold the picture long enough to compare. The visible evidence marker remains; methodology stays available in one disclosure.

These are transferable reasoning rules, not a requirement to duplicate the waterfall, violet card or dispatcher in every post-training scene.

## Scheduling's different argument

# September 24: teaching a paired comparison

These are portable reasoning rules, not a request to copy the scheduling card into every mechanism.

- **State the runtime's rule in ordinary language.** “Wait for both workers” versus “Start when a worker is free” comes before paired-batch or independent-admission terminology.
- **Make accounting accumulate from events.** A red idle interval contributes only its elapsed portion to the red ledger. Busy worker-time, avoidable idle worker-time, and user waiting time are different quantities. Keep units visible, and use a common axis when comparing quantities with the same unit.
- **Let each result receive a three-part reading.** Hold the underlying experiment fixed while highlighting baseline, optimized, then the exact difference for 3.5 seconds apiece. Do not keep changing the result while explaining it. Geometry can dim; labels must remain readable.
- **Put the difference on the data, not just in a number.** Bracket paired finish times, color only incremental completed requests, and connect the same emphasis to the consequence card.
- **Preserve identity through camera changes.** A cohort's request 7 cannot silently become request 1 because it is first in a new camera. Sequence position and persistent identity have different jobs.
- **Narration must not outrun the viewport.** Select only a fully exposed request with both endpoints inside the displayed horizon. Decorative difference overlays must never intercept clicks.
- **A semantic zoom explains grouping.** Ten visible agents can become ten groups and then one hundred groups. The population is revealed, not generated by the camera; groups are not GPUs, workers, or extra physical capacity. Carry recognizable members through each scale.
- **Name complementary outcomes without double-counting.** Delivery time, serving capacity, and GPU cost per correct answer are distinct questions. Capacity under a compute allowance and capacity at an elapsed-time deadline are two lenses, not two independent savings to add.
- **Evaluate delegated UI as a candidate.** Use disjoint files, a pure cursor-driven interface, explicit geometry and evidence limits. Review source and screenshots, then refine integration. Successful type checks do not establish visual quality.

## September 27: comparison lenses and an answer under pressure

- **A ratio is not a mechanism.** GPU work per correct answer changes when work changes, when the correct-answer count changes, or both. In the composition plot, isolate same-policy runtime pairs from same-runtime policy pairs. Expose numerator/denominator accounting on demand. A trained policy can cost more per task while solving more; preserve that tradeoff.
- **Map one claim to one visual interval.** The result card should receive a leader from the exact bracket or endpoint, not a nearby decorative symbol. Continue the bracket through unused plot space; do not route it across mechanism labels. On stacked layouts preserve labels and matching colors without long crossing lines.
- **Show the user's interruption as events.** An existing answer's emitted-token count should stop because the model's input-processing iteration excludes decode, not because an animation happens to pause. A resumed stream and a smaller inter-token gap then explain chunking without an essay.
- **Do not collapse two latency questions.** The longest gap in an existing answer and the wait for a new answer's first token are different intervals. Give each its own held view with the request identity attached. A scene can improve one and worsen the other.
- **Keep the practical layer on the technical clock.** Document progress, memory ownership, execution allocation, token marks and result values all project the same event trace. Do not invent a second token counter for the practical scene or show hardware activity after completion.
- **Inspection changes depth, not the experiment.** Preserve workload/configuration, cursor and identity when opening a detailed view. Pause at the transferred state. Returning to the film should not reset its selection. Test a second handoff after changing a parameter; initial defaults can conceal a broken transfer.
- **Use a counterexample that changes the cause.** Tight memory can keep a long prompt outside the device, so it cannot interrupt active decoding. Equal stream gaps are then meaningful, not a zero to hide. Keep the first-token cost and the boundary of the reservation model inspectable.

These are transferable rules, not a demand to reuse the two-machine layout for policy updates, speculation or placement. The main agent owns implementation following the user's rejection of Sol's visual direction.

## Matched-request replay: isolate before attributing

- A cohort average can conceal a cold request. Keep the average elsewhere and make specific warm/no-hit requests selectable when explaining reuse.
- Separate service-relative and arrival-relative coordinates. Waiting can disappear without reducing busy GPU work by the same amount. Label the clock's origin, not just its unit.
- Compare duration to duration, not the endpoints of differently positioned segments. Rebase decode work to a shared zero before bracketing its reduction.
- During playback, show live completion/token state. Reveal the final comparison after the residual interval has been observed; do not lead with a final saving while the picture is still establishing the request.
- Mechanism toggles must recompute the trace and its evidence record. Reuse-only must not inherit faster decode rates, and rate-only must not inherit a warm-prefix saving. Cache readiness can couple with timing, so isolated gains need not sum independently.
- Muting a lane should quiet geometry, not make request labels and unit text illegible. Keep the narrative legible in the baseline/optimized holds as well as the final state.

## Queue to percentile: earn the statistic

- A latency distribution is the consequence of completed requests. Show the arrival/queue/worker/completion states first; do not put unfinished requests into a final-cohort percentile during playback.
- Preserve identities through sorting. A point moves because its coordinate changes from arrival order to latency rank, not because a new population has been invented.
- A percentile compares independently ranked observations, not necessarily the same request. Give matched-request inspection a distinct state with both request IDs fixed. Do not connect two percentile endpoints as if task identity were invariant.
- Make the slow tail concrete. Color the observations beyond each boundary and derive counts from latency values, including ties. At p99 with 96 tasks, nearest rank is 96; there need not be any observation beyond it.
- Preserve state conservation on every event and between events: arrived = waiting + running + completed. Waiting excludes the two active workers; completion does not create an extra concurrent worker.
- Use exact staircase events for counts. Smooth only a presentation coordinate such as the sorting interpolation, never integer queue counts or request completion counts.
- Counterexamples must alter wording too. A sparse queue is not a busy queue with a hidden speedup. Equal intervals require an equality mark rather than a decorative gain.
- Keep full-run evidence serialization off the frame loop. Memoize stable record data while the presentation cursor changes; test exports after changing the selected experiment.

## A tour is a director, not a second implementation

- Reuse the accepted figure and its data projection in watch and inspect modes. A parallel "presentation plot" drifts into different means, defaults and evidence flags.
- Only one clock owns a directed tour. Child components can retain standalone playback, but their internal clocks must be disabled while receiving the director's cursor.
- A handoff is typed state: workload, checkpoint, budget, request identity, mechanism, measure, percentile, local cursor and selected comparison. A tab index alone is insufficient.
- Preserve both coordinates: the local component's time for inspection and the global tour's time for resuming the authored sequence. Explicitly selected metrics may open at a settled comparison without overwriting the saved tour position.
- Reduced motion should expose the chosen chapter's finished result, not its empty opening frame. Keep chapter-end shortcuts inside that chapter and aligned to the range input's step.
- A tour must not cover the figure with prose just because it has a narrator. Use the existing held difference and the mechanism-to-result connection; keep the surrounding cohort/settings visible.
- Keep the play/pause control reachable while the diagram is tall. Mobile layout must also reserve space for persistent site controls, not only fit the component's own bounding box.
- Route arrows around labels. Curved intervention annotations are acceptable when they avoid collisions, but do not use them to imply a measured continuous performance curve.

## September 29: discovery and the meaning of a falling line

- A heading should name the operation or metric in three to five words: prefill/decode scheduling, queue drainage, workload completion, response latency. Narrative sentences belong next to the visual consequence, not in every tab.
- Controls need visible purpose before interaction. Label checkpoint, runtime intervention and comparison measure; do not rely on a visitor discovering the entire interface by clicking unexplained words.
- A count falling is ambiguous without its population. Waiting requests fall when admitted; completed requests rise when finished. Show both and name the event. Do not describe a falling queue as falling throughput.
- Freeze coordinates during a causal comparison unless a camera change itself is explicitly taught. A moving time horizon can make an unchanged historical trace appear to collapse.
- Conclude before translating representation: finish and hold the workload, expose the endpoint difference, then rank latency. A finished data model without a held visual conclusion still feels unfinished.
- Contributions are ordered counterfactuals, not percentages borrowed for mechanism labels. Cache reuse first, then changed execution rates, preserves a reconciled cost sum; the order is part of the claim.
- Standard terms sharpen, not replace, meaning: TTFT for time to first token, maximum ITL for the longest inter-token interruption, TPOT for a mean time per output token. Never rename the maximum gap as TPOT.
- Verify the process cwd behind a preview port. A healthy response from a different checkout is not verification of current work.
